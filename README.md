# Кафе-бар

Курсовой проект: локальное настольное приложение для управления небольшим кафе-баром. Технологии: C#, WPF, .NET 8, Entity Framework Core 8 и SQLite. План реализации находится в [docs/plan.md](docs/plan.md), описание базы данных — в [docs/data-model.md](docs/data-model.md).

## Состояние проекта

- Этап 1: создано главное окно и переключение между разделами.
- Этап 2: модель данных сделана строго по диаграммам (15 классов и 15 таблиц), подключены EF Core и SQLite. Локальная база создаётся и обновляется миграциями при запуске приложения.
- Этап 3: вход по логину и паролю и карточки сотрудников в разделе «Персонал». Пароли хранятся только в виде хэша. Разграничения доступа по ролям ещё нет (этап 4): раздел «Персонал» пока открыт любому вошедшему сотруднику. Остальные разделы остаются заглушками.
Этап 4: роли и разграничение доступа к разделам; регистрация начала и завершения смены кнопкой в левой панели (таблица Shifts).
- Этап 5: категории и позиции меню — добавление, изменение, удаление, переключение доступности. Менять меню может только администратор, остальные роли видят список
## Запуск

Нужны Windows 10/11 x64 и .NET 8 SDK с поддержкой WPF (или Visual Studio 2022 с компонентом «Разработка классических приложений .NET»). Для первой сборки нужен интернет: загружаются пакеты NuGet.

В терминале из корня проекта:

```powershell
dotnet run --project .\CafeBar\CafeBar.csproj
```

Для проверки сборки без запуска: `dotnet build .\CafeBar\CafeBar.csproj`.

## Вход и сотрудники

При первом запуске сотрудников в базе нет, поэтому приложение предлагает создать администратора. После этого открывается окно входа; под созданным логином и паролем открывается главное окно. Кнопка «Выйти» в левой панели возвращает к окну входа.

Проверка этапа 3:

1. Создайте администратора и войдите под ним.
2. Откройте раздел «Персонал», добавьте сотрудника, измените его карточку.
3. Нажмите «Выйти» и войдите под новым сотрудником. С неверным паролем вход не выполняется.
4. Откройте файл базы (см. раздел «База данных»): в таблице `Employees` в столбце `PasswordHash` находится строка вида `PBKDF2-SHA256$600000$…`, самого пароля в базе нет. Формат этой строки описан в [docs/data-model.md](docs/data-model.md).

В карточке сотрудника поля взяты с диаграмм: ФИО, роль, логин, пароль, процент от продаж. Должность и роль по ТЗ (администратор, официант/бармен, кладовщик) задаются одним полем «Должность (роль)» и хранятся в `Employees.Role`. Логин не зависит от регистра букв и не может повторяться. Удалить нельзя себя, единственного администратора и сотрудника, на которого ссылаются другие записи.

Если войти не удаётся (например, забыт пароль единственного администратора), закройте приложение и удалите файлы `cafebar.db*`: база создастся заново, и приложение снова предложит создать администратора. Все данные при этом удаляются.

## База данных

При запуске приложение создаёт файл `%LOCALAPPDATA%\CafeBar\cafebar.db` и применяет к нему миграции из `CafeBar/Migrations`. Если базу открыть не удалось, приложение показывает сообщение с причиной и закрывается.

Проверка этапа 2: после первого запуска в папке `%LOCALAPPDATA%\CafeBar` появляется файл `cafebar.db`. В нём 15 таблиц модели и две служебные: `__EFMigrationsHistory` и `sqlite_sequence`. Посмотреть их можно, например, в DB Browser for SQLite. Чтобы начать с чистой базы, закройте приложение и удалите файлы `cafebar.db*`.

После изменения классов таблиц (`CafeBar/Modules/*/Data`) или `CafeBarDbContext` нужна новая миграция:

```powershell
dotnet tool install --global dotnet-ef --version 8.0.34
dotnet ef migrations add MigrationName --project .\CafeBar\CafeBar.csproj
```

Она применится при следующем запуске приложения.

## Структура

- `CafeBar/MainWindow.xaml` — разметка окна.
- `CafeBar/ViewModels/MainViewModel.cs` — выбранный раздел и его содержимое.
- `CafeBar/Commands/RelayCommand.cs` — команда для кнопок навигации.
- `CafeBar/App.xaml.cs` — запуск: подготовка базы, вход и открытие главного окна.
- `CafeBar/ViewModels/ViewModelBase.cs` — общая основа моделей представления.
- `CafeBar/Modules/` — модули по функциональным областям из ТЗ: `OrderManagement` (заказы), `MenuManagement` (меню), `Inventory` (склад), `TechCards` (техкарты), `StaffManagement` (персонал), `Administration` (администрирование). Внутри модуля код делится на слои: `Data` — работа с данными (классы таблиц), `Logic` — логика, `UI` — интерфейс. Слои `Logic` и `UI` пока есть только у модуля `StaffManagement`.
- `CafeBar/Modules/StaffManagement/Logic/` — хэширование паролей (`PasswordHasher`), роли (`EmployeeRoles`), карточки и вход (`EmployeeService`), текущий сеанс (`Session`).
- `CafeBar/Modules/StaffManagement/UI/` — окно входа, список сотрудников и карточка сотрудника.
- `CafeBar/Data/CafeBarDbContext.cs` — общий контекст базы данных для всех модулей.
- `CafeBar/Data/AppDatabase.cs` — путь к файлу базы, создание контекста, применение миграций.
- `CafeBar/Data/CafeBarDbContextFactory.cs` — создание контекста для команд `dotnet ef`.
- `CafeBar/Migrations/` — миграции.
- `docs/plan.md` — этапы и вопросы по исходным материалам.
- `docs/data-model.md` — модель данных и её соответствие диаграммам и ТЗ.
- 'AccessPolicy' - права по ролям
- 'ShiftService' - смены
- MenuService.cs: вся работа с базой для категорий и позиций.
- MenuViewModel.cs: данные для экрана «Меню».
- MenuView.xaml и .xaml.cs: сам экран с двумя вкладками.
- CategoryWindow: окно «Категория» с одним полем названия.
- MenuItemWindow: окно «Позиция меню» с категорией, названием, ценой, единицей, описанием и флагом доступности.
